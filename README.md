# FC DKP · Sleeping Forest · RF Online

Сохранённая версия **1.0.5**, архив от **12.09.2026**.
Репозиторий содержит исходники и шаблон `.env.example`.
Рабочая база DKP, журналы и токен в репозиторий не включены.
Изменения для публикации: расширен `.gitignore`, ID в офлайн-проверке заменён
на тестовое значение. Основная логика бота сохранена.

Discord-бот для локального запуска на Windows. Управление через команды и кнопки; данные — в SQLite на вашем компьютере. Отдельный сайт и платный сервер не нужны. Бот использует исходящее соединение с Discord: открывать порты или настраивать веб-сервер не требуется.

## Что уже реализовано

- Привязка игрового ника к Discord ID; смена ника офицером сохраняет баланс.
- События ЧВ/ПБ/сборы: отметки кнопкой, добавление из голосового канала, исправление состава.
- Массовое начисление только после проверки состава и подтверждения офицером.
- Аукционы предметов с кнопкой ставки, резервом очков, автоматическим завершением и списанием победителю.
- Балансы, таблица участников, история каждого участника и общий журнал.
- Корректировка ДКП с обязательной причиной и подтверждением.
- Восстановление кнопок и открытых аукционов после перезапуска.
- Резервные копии при запуске, раз в день работы и по команде.
- Фоновый запуск после входа в Windows под вашей учётной записью, с перезапуском при сбое и использованием того же Python, что и start.bat.
- Быстрое подтверждение запросов, ответы на ошибки и устаревшие кнопки, диагностика через `/dkp status`.

Бот не подключается к RF Online. Название предмета вводит офицер, участие в игре он подтверждает вручную. Присутствие в голосовом канале — вспомогательный список, не доказательство участия в ЧВ/ПБ. Предмет победителю передаётся вручную в игре.

## 1. Подготовьте Discord-приложение

Создайте отдельное приложение **FC DKP** в [Discord Developer Portal](https://discord.com/developers/applications). Отдельное приложение нужно, чтобы не менять команды уже работающего бота: этот проект синхронизирует собственный набор `/dkp` для указанного сервера.

1. Нажмите **New Application**, задайте имя `FC DKP`.
2. В разделе **Bot** получите токен: **Reset Token** / **Copy**. Сохраните его для локального ввода на шаге 3. Токен не отправляйте в чат или участникам гильдии.
3. В **Installation → Installation Contexts** включите **Guild Install**. User Install не нужен.
4. В **Default Install Settings → Guild Install** выберите scopes **bot** и **applications.commands**.
5. Выдайте боту права: **View Channels**, **Send Messages**, **Embed Links**, **Attach Files**, **Read Message History**. Право **Administrator** боту не требуется.
6. Откройте **Install Link → Discord Provided Link**, выберите **Add to server** и свой сервер FC.
7. Поле **Interactions Endpoint URL** оставьте пустым: этот бот получает события через Gateway.
8. **Privileged Gateway Intents** включать не нужно. Чтение текста сообщений и полный список участников бот не запрашивает.

Если у вас отображается раздел **OAuth2 → URL Generator**, можно сформировать приглашение там: scopes `bot` + `applications.commands`, те же пять прав. Используйте один способ установки.

Основание: [официальная инструкция Discord](https://docs.discord.com/developers/quick-start/getting-started), [Gateway intents discord.py](https://discordpy.readthedocs.io/en/v2.6.4/intents.html). Здесь используется Gateway-клиент Python, поэтому публичный HTTP endpoint из JavaScript-примера Discord не нужен.

## 2. Подготовьте канал, роли и ID сервера

- Создайте текстовый канал **📊дкп** в разделе RF Online.
- Создайте роль **ДКП-офицер** и выдайте ответственным за распределение лута.
- Для участников можно использовать существующую роль **⚔️ Состав FC**.
- Разрешите этим ролям просмотр ДКП-канала и использование команд приложений (**Use Application Commands**). Для получения файлов со списком/журналом нужен доступ к каналу.
- Проверьте, что в канале боту разрешены все пять прав из шага 1. Если используете `/dkp voice`, разрешите ему **View Channel** также для нужного голосового канала. Подключаться к голосу ему не нужно.

Чтобы скопировать ID сервера:

1. Discord → **Настройки пользователя → Расширенные → Режим разработчика**.
2. Правой кнопкой по иконке сервера FC → **Копировать ID сервера**.

Нужен именно **ID сервера**, не ID приложения, роли или канала.

## 3. Установите и запустите на Windows

1. Распакуйте весь архив в постоянную папку, например `C:\Bots\FC-DKP`. Запускать из окна ZIP-архива нельзя.
2. Нужен Python 3.11–3.14; для этого проекта рекомендуется Python **3.12**. При обычной установке включите **Add Python to PATH**.
3. Запустите **install.bat**. Скрипт создаст `.venv`, установит зависимости и выполнит проверки. Дождитесь `Installation complete`.
4. Запустите **configure.bat**. Введите токен бота и ID сервера. Ввод токена скрыт — отсутствие символов на экране нормально. Настройки сохранятся в `.env`.
5. Запустите **start.bat**. Дождитесь `FC DKP 1.0.5 online`.
6. Оставьте окно работающим. Остановка: **Ctrl+C**. Повторный запуск: **start.bat**.

Компьютеру нужен интернет и доступ к Discord, в том числе Python-процессу, а не только приложению Discord. Для первоначальной установки нужен доступ к PyPI. После установки пакетов PyPI для работы бота не требуется.

Альтернатива настройщику: скопировать `.env.example` в `.env` и заполнить `DISCORD_TOKEN` и `GUILD_ID` вручную. `DATA_DIR=data` можно оставить. При повторном запуске `configure.bat` он явно предложит заменить `.env` и вернёт DATA_DIR к `data`.

## Фоновый запуск после входа в Windows (1.0.5)

Бот запускается без видимого окна под вашей обычной учётной записью через тот же `.venv\Scripts\python.exe`, который использует `start.bat`. Это сохраняет пользователя и исполняемый файл из работающего обычного запуска, что важно для VPN с выбором приложений. Планировщик запускает скрытый PowerShell, который запускает Python, ждёт его завершения и передаёт код ошибки для перезапуска. `pythonw.exe` больше не используется.

**При переходе с 1.0.3/1.0.4:** один раз запустите `autostart_off.bat` **от администратора**, чтобы удалить прежнее задание SYSTEM. Новое задание создавайте обычным запуском `autostart_on.bat`. Если вы случайно запустите включение от администратора, скрипт попросит открыть его обычным двойным щелчком.

1. Подключите VPN с теми правилами для Python, при которых работает `start.bat`.
2. Остановите обычного бота через Ctrl+C; уберите старое задание SYSTEM, если оно есть.
3. Запустите `autostart_on.bat` **обычным двойным щелчком**. Администратор и пароль не нужны.
4. После сообщения `Autostart enabled: current user...` окно установщика можно закрыть.
5. Проверьте `/dkp status`: версия **1.0.5**. При проблеме запустите `autostart_status.bat`; в строке Account должна быть ваша учётная запись, Logon type — Interactive.

| Файл | Действие |
|---|---|
| `autostart_on.bat` | Создать/обновить пользовательское задание и запустить сейчас. При повторном включении управляемый процесс перезапускается |
| `autostart_status.bat` | Учётная запись, состояние задания и строки журнала после последнего запуска задания |
| `autostart_off.bat` | Остановить и удалить задание этой папки. Настройки и ДКП сохраняются |

Запуск при входе в Windows имеет задержку 30 секунд. При завершении Python с ошибкой Планировщик повторяет запуск через минуту, до 999 попыток; время каждой попытки подключения добавляется к этому интервалу. Ограничение длительности работы задания отключено. Если VPN запускается вручную, подключите его после входа и дождитесь повторной попытки. Убедитесь, что пользовательская VPN-политика разрешает Python в фоновом режиме: это проверяется на вашем ПК.

`Running` означает работу процесса. Готовность бота подтверждается свежей строкой `FC DKP 1.0.5 online` и ответом `/dkp status`. Статус больше не показывает старые строки `online` за предыдущие дни как часть последнего запуска. Журналы находятся в `logs/background.log` и `logs/bot.log`.

Компьютер должен быть включён, пользователь — вошедшим в Windows, VPN — подключён. Можно заблокировать экран через Win+L, сохранив сеанс; выход из учётной записи, сон или выключение остановят доступность бота. **До входа в Windows этот режим не работает.** Для независимости от ПК нужен перенос на удалённый сервер.

Перед обновлением или перемещением папки отключите автозапуск, затем после замены файлов включите снова. Скрипт управляет только заданием `FC-DKP-…`, привязанным к пути этой установки; чужие задания с несовпадающим описанием не заменяются.

Настройки основаны на [Interactive principal](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/new-scheduledtaskprincipal), [триггере входа](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/new-scheduledtasktrigger) и [скрытом запуске процесса с ожиданием](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.management/start-process?view=powershell-5.1).

## 4. Однократная настройка внутри Discord

Администратор сервера выполняет команду, выбирая значения в полях Discord:

```text
/dkp setup channel:📊дкп officer_role:ДКП-офицер member_role:⚔️ Состав FC
```

Если `member_role` не указать, пользоваться ДКП смогут все участники сервера. С указанной ролью — её обладатели, офицеры и администраторы. Все дальнейшие команды выполняются в выбранном текстовом ДКП-канале.

Затем в **📊дкп**:

```text
/dkp panel
```

Появятся кнопки **Привязать ник**, **Мой баланс**, **Таблица ДКП**, **Моя история**. Панель можно закрепить средствами Discord. Участники привязывают свой настоящий игровой ник. Смена ника доступна через офицера; один Discord ID имеет один баланс.

В первой версии канал закрепляется за базой и не переносится через команду, чтобы не потерять действующие карточки и сообщения. Роли можно поменять повторным `/dkp setup` с тем же каналом.

## 5. Как провести ЧВ или ПБ

1. Офицер создаёт событие, например:

   ```text
   /dkp event title:ЧВ вечер points:10
   ```

2. Бот публикует карточку. Участники нажимают **Я участвую**. Пока начисления нет, они могут нажать **Убрать меня**.
3. По желанию офицер добавляет зарегистрированных людей, которые сейчас находятся в голосовом канале:

   ```text
   /dkp voice event_id:1 channel:название_голосового_канала
   ```

   Номер берётся с карточки. Уже добавленные не дублируются. Боты, люди без роли или без зарегистрированного ника пропускаются. Это однократный снимок, автоматического начисления за время в голосе нет.

4. Офицер проверяет полный состав кнопкой **Состав** или `/dkp roster event_id:1`. Список скачивается как текстовый файл.
5. Исправляет состав при необходимости:

   ```text
   /dkp event_add event_id:1 member:@игрок
   /dkp event_remove event_id:1 member:@игрок
   ```

6. Нажимает **Проверить и начислить**. Ему показываются сумма, количество и полный состав. После **Подтвердить** очки начисляются всему списку одной транзакцией. Если состав изменился после открытия подтверждения, бот попросит проверить его заново.

Повторное подтверждение того же события ничего не начислит. Чтобы исправить уже начисленные очки, используется `/dkp adjust` с причиной.

## 6. Аукцион

```text
/dkp auction item:Щит 45 уровня minimum:10 step:1 minutes:10
```

Название предмета свободное: укажите уровень, тип и улучшение так, чтобы участники понимали, что покупают. Каждая карточка — один предмет или один явно описанный комплект. Скриншот можно отправить рядом вручную.

Участник нажимает **Сделать ставку** и вводит полную сумму. Например, `25` означает ставку 25 ДКП, а не прибавку 25 к предыдущей.

Правила первой версии:

- Старт, шаг и продолжительность задаёт офицер при создании. Цена победителя — его последняя принятая ставка.
- Ставка должна быть не ниже старта, затем не ниже текущей ставки плюс шаг. При равной сумме новая ставка отклоняется.
- Пока игрок лидирует, сумма зарезервирована. Этот резерв нельзя потратить на другом аукционе или списать корректировкой.
- Если игрока перебили, его резерв освобождается. Повышение собственной ставки заменяет предыдущий резерв.
- Ставка в последние 30 секунд переносит конец на 30 секунд после неё.
- Самостоятельно снять ставку нельзя. Офицер может отменить ещё не истёкший аукцион командой `/dkp cancel` с причиной и подтверждением; резерв освобождается.
- По завершении списываются очки только победителя. Передачу вещи выполняет офицер в игре.
- При выключенном/спящем ПК или отсутствии сети ставки не принимаются. Время конца хранится как абсолютное время: после запуска просроченный аукцион рассчитывается по последней принятой ставке. **Таймер не ставится на паузу.** Планируйте аукционы на время работы компьютера.

## Первый пробный проход

На первом запуске реальных данных ещё нет. Зарегистрируйте свой ник кнопкой или командой, создайте событие **Тест запуска** на **1 ДКП**, отметьтесь и подтвердите начисление. Создайте аукцион **Тест — предмет не выдаётся** со стартом 1, шагом 1 и временем 1 минута. Поставьте 1 ДКП и дождитесь завершения. Баланс вернётся к нулю, а в истории останутся две понятные тестовые записи.

Дополнительно проверьте с обычной ролью участника, что `/dkp adjust` и подтверждение начисления недоступны. Содержательные проверки учёта включены в `install.bat`; проверка связи с вашим сервером выполняется этим пробным проходом.

## Хранение и восстановление

- `.env` — токен и ID сервера. Не включайте в публикации исходников.
- `data/dkp.sqlite3` — основная база. При работающем SQLite рядом могут быть файлы `-wal` и `-shm`; они являются частью текущего состояния.
- `data/backups/` — резервные копии. Команда `/dkp backup` создаёт согласованную копию даже при работающем боте.
- `logs/bot.log` — ID запроса, операция, время обработки, задержка получения, HTTP-код и тип ошибки, события подключения/разрыва Gateway. Журнал имеет ротацию; финансовая история ДКП хранится в базе и журнале Discord. Токен и содержимое HTTP-запросов в этот журнал не записываются.
- `logs/background.log` — запуск, подключение и остановка фонового процесса; журнал также имеет ротацию.

Для переноса сначала выполните `/dkp backup`, затем остановите бот (для фонового режима — `autostart_off.bat` в старой папке). Перенесите проект и папку `data`, снова установите зависимости, настройте `.env` и запустите. Не запускайте две копии на разных компьютерах с раздельными копиями одной базы: они будут вести независимый учёт. От двойного запуска с одной локальной базой есть блокировка.

Для восстановления из копии: остановите бот, **переименуйте всю текущую папку `data`**, создайте новую `data`, скопируйте выбранный файл из `backups` туда под именем `dkp.sqlite3` и запустите с прежним GUILD_ID. Так старые `-wal`/`-shm` не смешаются с восстановленной базой. Восстановление возвращает баланс к моменту копии; более новые сообщения Discord сами не удаляются. Свежие события после восстановления нужно сверить с офицерами.

Храните периодические копии базы также вне этого ПК. Локальные копии не защищают от поломки диска. Копии не удаляются автоматически; при долгой работе их можно вручную переносить/чистить.

## Если что-то не работает

| Симптом | Что проверить |
|---|---|
| `Python was not found` | Установлен ли Python и доступен ли `py -3` / `python` |
| Установка пакетов не прошла | Доступ Python/pip к PyPI, текст ошибки в окне install.bat |
| `Discord rejected the bot token` | Токен именно из раздела Bot, без пробелов; снова configure.bat |
| `Discord denied access` | Верный GUILD_ID, приложение установлено на сервер, scopes `bot` и `applications.commands` |
| Команда `/dkp` не видна | Бот пишет `online`; выбран правильный сервер; разрешено Use Application Commands; обновите Discord |
| «Приложение не отвечает» | Проверьте версию 1.0.5 через `/dkp status`, свежую строку `online` и `logs/bot.log`. Компьютер должен работать, а Python иметь доступ к Discord. При повторном сбое сохраните точное время, название команды и журнал |
| Автозапуск выдаёт отказ в доступе | Удалите старое задание SYSTEM через autostart_off.bat от администратора. Новый autostart_on.bat запустите обычно. Если отказ сохраняется, пришлите точный текст ошибки |
| В фоне бот не подключается | autostart_status.bat: Account должен быть вашим пользователем, Logon type — Interactive. Проверьте VPN для основного python.exe и свежие строки background.log |
| Карточки/журнал не появляются | Права бота на ДКП-канал. После исправления очередь публикаций отправится автоматически |
| Кнопка после перезапуска не работает | Дождитесь `online`; незавершённые подтверждения нужно открыть заново |
| ДКП вроде начислены, но ответа нет | Сначала проверьте balance/history/journal: база могла успеть сохранить операцию до обрыва связи |

Уведомления доставляются из очереди. При редком обрыве между отправкой сообщения Discord и сохранением подтверждения доставки может повториться **сообщение** с тем же номером записи. Само начисление/списание от этого не повторяется. Карточки обновляются примерно раз в 5 секунд с учётом ограничений Discord.

## Для разработки

Python 3.12, discord.py 2.6.4, python-dotenv 1.2.1. Проверки:

```bash
python -m unittest discover -s tests -v
python check.py
```

После установки requirements.txt первая команда запускает весь набор тестов, включая обработчики всех команд и кнопок, формы, имитацию сетевых отказов и одновременных запросов. Вторая проверяет создание команд, постоянных кнопок, форм и восстановление интерфейса без токена и без подключения к Discord. `install.bat` выполняет обе. Без сторонних пакетов доступны только 29 тестов учёта, прав и фонового запуска; для полной проверки нужно установить зависимости.

Разделение кода: `store.py` — транзакции и журнал; `policy.py` — правила доступа; `bot.py` — Discord; `responses.py` — подтверждения, доставка ответов и диагностика; `database_io.py` — отдельные очереди чтения, записи и резервного копирования; `runtime.py` — блокировка второго запуска; `configure.py` — локальная настройка; `background.py` — запуск без консоли и журнал; `autostart.ps1` — управление заданием Windows; `run_background.ps1` — скрытый запуск python.exe с передачей кода завершения.

Проверено при сборке 1.0.4: **80 тестов, все прошли, пропусков нет**, и `check.py` с **23 командами**, постоянными кнопками, формами и восстановлением после перезапуска. Среда: Linux, Python 3.12, discord.py 2.6.4, python-dotenv 1.2.1, aiohttp 3.13.5. Проверены:

- Все slash-команды, кнопки панели/событий/аукциона/подтверждения и обе формы.
- Обработка запросов настоящими CommandTree, ViewStore и Interaction из discord.py; HTTP-ответы Discord имитируются.
- 100 одновременных запросов: баланс, ставки и отметки участия; занятая SQLite не блокирует чтение и первоначальное подтверждение.
- Ошибки доступа, устаревшие кнопки/формы, истёкшее подтверждение, отказ или задержка первоначального ответа.
- Повторная доставка ответа и файла после сетевого сбоя без повторного начисления; атомарный отказ сбора голосового состава.
- Закрытие аукциона при задержанной публикации, сохранение выполняющейся транзакции при отмене ожидающей задачи, резервирование и защита от повторных списаний.
- Сохранение истории и баланса при смене ника, закрытие файлов резервной копии, блокировка второй копии бота, запуск Python без консоли.

На коде 1.0.3 отдельно воспроизведён выход `RuleError` из проверки прав в CommandTree после подтверждения запроса без итогового ответа. На 1.0.4 этот сценарий получает текст ошибки. Подключение к вашему Discord-серверу и создание задания Windows в среде сборки не проверялись: нет вашего токена и Windows/PowerShell. Проверки установки повторяются на вашем ПК; в Windows после включения автозапуска проверьте `/dkp status` сразу и после перезагрузки.

Исправление 1.0.1: соединение с файлом резервной копии закрывается явно, в том числе при ошибке копирования. Это устраняет удержание файла, из-за которого Windows выдавал `WinError 32` при очистке временной папки теста. Добавлена проверка закрытия обоих соединений при успехе и ошибке. Она воспроизводила утечку на старом коде и проходит после исправления.

Исправление 1.0.2: `/dkp balance` и кнопка «Мой баланс» подтверждают запрос до проверки доступа и чтения базы. Остальные команды и кнопки с текстовым ответом также подтверждают запрос заранее; кнопки открытия форм сразу отвечают формой. Запросы SQLite, включая фоновые операции, выполняются вне основного цикла Discord. Баланс читается в согласованной транзакции без захвата блокировки записи. Повторное подтверждение или отмена операции во время её выполнения блокируются. Это устраняет задержки из-за базы перед первоначальным ответом, который [Discord требует отправить в течение 3 секунд](https://docs.discord.com/developers/interactions/receiving-and-responding).

Обновление 1.0.3: добавлен фоновый запуск при загрузке Windows через Планировщик заданий, перезапуск после сбоя и отдельный журнал. Скрипты включения, проверки и удаления автозапуска находятся в корне проекта.

Обновление 1.0.4: первоначальное подтверждение отправляется в общей точке входа команд; ошибки проверок доступа завершают запрос понятным ответом. Устаревшие кнопки и формы получают ответ с указанием открыть команду заново. Формы открываются без чтения базы, а их отправка ограничена по времени. Чтение, запись и резервные копии используют отдельные рабочие потоки. Расчёт аукционов работает отдельно от публикации Discord. Обычные сетевые обращения, создание копии и загрузка голосового состава имеют предел ожидания; после успешного изменения данных повторяется только доставка ответа, а не действие. Добавлены `/dkp status`, журнал времени запросов и защита длины сообщений с Unicode.

Обновление устраняет найденные программные причины отсутствия ответа. Оно не может доставить ответ, если компьютер выключен/спит или Discord недоступен по сети. Без журнала с компьютера, на котором происходил сбой, нельзя приписать все прошлые отказы одной причине. Если сбой повторится на 1.0.5, сохраните `logs/bot.log` и сообщите точное время и команду; `.env` для диагностики не нужен.

Обновление 1.0.5: задание SYSTEM при загрузке заменено пользовательским заданием при входе в Windows. Используется скрытый `python.exe`, как в рабочем start.bat, с сохранением кода завершения для перезапуска. Проверка статуса показывает учётную запись и только свежие строки фонового журнала. В install.bat добавлена проверка синтаксиса PowerShell и построения задания без его регистрации. Повторное включение обновляет и перезапускает своё задание, старые SYSTEM-задания требуют предварительного удаления.

Для обновления см. `UPDATE_RU.txt`. Перед заменой файлов остановите start.bat через Ctrl+C и удалите старое задание SYSTEM: `autostart_off.bat` от администратора. Скопируйте содержимое `fc-dkp-bot` из архива в установленную папку с заменой файлов. Папку целиком не удаляйте: сохраните `.env`, `data`, `logs` и `.venv`; в архиве их нет. Запустите `install.bat`, затем `autostart_on.bat` **обычным двойным щелчком**. Повторять configure.bat или `/dkp setup` не нужно. `/dkp status` должен показать **1.0.5**.

Проверки сборки 1.0.5: повторный прогон 80 Python-тестов и check.py. Реальный Планировщик Windows и ваш VPN в Linux недоступны; проверка PowerShell и построения задания выполняется install.bat на вашем ПК. Проверка реальной работы — ответ `/dkp status` после включения нового автозапуска и после повторного входа в Windows с подключённым VPN.

Запуск на Linux/macOS возможен через venv, установку requirements.txt, `python configure.py` и `python bot.py`. В текущем комплекте сценарии запуска подготовлены для Windows.
